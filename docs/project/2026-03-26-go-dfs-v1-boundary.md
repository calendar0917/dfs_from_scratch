# go-dfs v1 边界说明

## 目标

这份文档定义当前 `go-dfs v1` 可以稳定宣称的能力边界。

用途只有三个：

1. 限制项目 scope，防止继续横向扩张
2. 给 README 与项目技术说明提供统一边界
3. 区分“已经做到”“能演示”和“还不能宣称”

## 一句话定义

`go-dfs v1` 是一个基于 Go 和 gRPC 的简化分布式文件存储实验项目，展示 `Master / Volume` 分离、链式复制、一致性哈希、副本分配和本地多节点运行闭环。

它不是生产级分布式文件系统。

## 当前可以稳定宣称的能力

以下能力已经有代码实现和本地验证支撑，可以写入 README 和项目技术说明。

### 1. 基本架构能力

- 使用 `Master` 管理节点注册、心跳和文件位置元数据
- 使用 `Volume` 负责本地文件存储和对下游节点的数据转发
- 使用 `Client` 负责上传和下载流程
- 使用 gRPC + Protobuf 定义服务接口和流式传输协议

### 2. 写入路径能力

- 客户端上传时先向 `Master` 请求副本链路
- `Master` 能基于一致性哈希返回多个副本地址
- 客户端能向首个 `Volume` 发起流式上传
- `Volume` 能将元数据和数据块继续向下游节点链式转发
- 上传结束后，客户端可以收到成功回执

### 3. 读取路径能力

- 客户端可先从 `Master` 获取文件位置
- 客户端可直接从某个 `Volume` 进行流式下载
- 下载文件内容可与上传源文件一致

### 4. 节点管理能力

- `Volume` 启动后能向 `Master` 注册
- `Volume` 能周期性发送心跳
- 心跳超时后，`Master` 能将节点从可用节点列表中剔除

### 5. 本地运行与验证能力

- 可本地启动 `1 Master + 3 Volume`
- 有统一的启动、停止、清理脚本
- 有最小 smoke test，验证上传、下载和内容一致性
- `go test ./...` 与 `make build` 可以通过

## 当前能演示但仍需谨慎表述的能力

以下能力可以演示，但不应写成过强承诺。

### 1. 三副本写入链路

当前系统可以走通三节点链式写入，但这不等于已经具备成熟的副本修复、再平衡和完整容灾能力。

### 2. 元数据持久化

`Master` 可以将元数据写到本地文件并在重启时读取，但这只是单节点本地持久化，不是高可用元数据方案。

### 3. 连接池

代码中实现了 gRPC 连接池，链式复制路径也会使用它，但这更适合作为工程实验点，而不是当前版本的核心卖点。

## 当前明确不支持的能力

以下能力在 `go-dfs v1` 中明确不支持，不应写成“已实现”或“基本完成”。

- `Master` 高可用
- 共识协议，例如 `Raft`
- 自动副本修复
- 节点上下线后的自动数据迁移或再均衡
- 严格定义的 `Quorum` 读写一致性策略
- 认证、鉴权、租户隔离
- 监控指标、报警和可观测性体系
- Docker 化部署、远程集群部署、生产环境运维
- 完整的端到端故障注入测试

## 当前不应该使用的表述

以下表述在当前版本中不够严谨，应该避免：

- “生产可用”
- “具备完整容灾能力”
- “支持高可用 Master”
- “支持自动数据修复”
- “实现了工业级一致性保证”
- “性能提升 1000x，因此系统已经足够高性能”

如果要提性能相关内容，应该限定为：

- 本地 benchmark 或优化实验结果
- 某个实现细节上的局部性能观察
- 不代表生产环境整体性能承诺

## 当前版本的最小完成标准

只有同时满足以下条件，才可以对外称为 `go-dfs v1`：

1. `go test ./...` 通过
2. `make build` 通过
3. `make cluster-start` 可以启动本地多节点集群
4. `make smoke-test` 可以通过
5. README 的能力声明与当前代码一致

## 下一阶段只允许新增的一个方向

下一阶段只允许选择一个方向继续推进，避免同时扩展多个主题。

推荐方向：`工程化与验证增强`

具体只做这类工作：

- 清理 `runtime/` 产物处理方式
- 完善 README 和运行说明
- 增加更多 smoke / integration 验证
- 补充失败场景的验证脚本
- 让集群生命周期脚本更稳

下一阶段不建议直接进入：

- `Raft`
- 自动迁移
- 自动修复
- 指标系统
- 大规模架构扩展

原因很简单：
当前项目最值钱的增量，不是再加新名词，而是把已经存在的主路径做得更稳、更可解释、更可复现。
